# Nandina 1.0 Acceptance Contract

> Release contract for the C++26 line developed in `nandina_experiment` and promoted to the
> official `NandinaUI` repository.

## 1. Purpose

Nandina 1.0 is not defined by adding more widgets. The existing scene, reactive, layout, text,
theme, router, animation, resource, and semantic layers already form the runtime core. The 1.0
closure line makes one ordinary desktop application reproducibly creatable, buildable, runnable,
resource-complete, testable, and promotable to the official repository.

This document is the acceptance authority for that closure line. `WORKFLOW.md` defines how each
reviewable unit is implemented and verified; `1.0_PROMOTION_PLAN.md` defines how the accepted tree
is transferred to the official repository.

## 2. Supported Release Profile

The minimum 1.0 support promise is deliberately narrow:

- Linux desktop on the raylib/GLFW window and raylib render backend.
- C++26 with GCC 16+ or Clang 21+ and a matching standard library that provides `std::expected`,
  `std::move_only_function`, and `std::println`.
- Meson >= 1.3 + Ninja >= 1.10 as the supported build path; CMake, Python 3, pkg-config, Git, and
  OpenSSL >= 3.0 are required by the current source/resource toolchain.
- GNOME Wayland sessions using the current X11/XWayland window backend require `wl-clipboard` for
  reliable text clipboard exchange with native Wayland applications.
- Nandina consumed from a locked, hash-verified SDK source artifact by default. Recursive Git
  submodules and local paths remain explicit contributor/development providers.
- One application process with one ordinary window; nested keep-alive routers are supported.
- Mouse and keyboard interaction, focus traversal, committed Unicode text input, CJK font fallback,
  light/dark themes, reduced-motion policy, resources, images, and custom fonts.
- Source delivery first. An installed SDK is supported only if public headers, dependency metadata,
  resource helpers, and an install-consumer fixture are completed before the release candidate.

The README and release notes must call this a Linux 1.0. Windows and macOS must not be implied by
raylib's upstream platform support while `NanApplicationConfig::for_process` and resource location
remain Linux-specific.

## 3. Explicit Non-Goals

The following work is useful but does not block the Linux 1.0 release unless a later decision moves
it into the supported profile:

- Windows/macOS process, resource, input, packaging, and appearance adapters.
- Multi-window, offscreen surfaces, Vulkan/SDL backends, audio, and application-store packaging.
- Platform accessibility bridges beyond the internal semantics tree and keyboard navigation.
- Rich text, color emoji, UAX #14 line breaking, ligature-internal carets, gestures, and drag/drop.
- Anchor layout, complete CSS flexbox, scrollbar chrome, kinetic scrolling, dirty-only paint,
  damage tracking, and retained render caches.
- 9-patch, atlas, component motion slots, i18n language packs, and additional example templates.

## 4. Acceptance Gates

### G1. Reproducible Source Build

- The supported compiler and tool versions are documented and checked by `nandina doctor`.
- A clean SDK source bundle followed by Meson setup and compile succeeds without an undeclared
  checkout path; the recursive Git provider is covered separately.
- Default and SQLite-fallback builds are covered.
- Optional physics remains disabled by default and is covered by a separate enabled build.
- No test-only dependency is required when Nandina is consumed with `build_tests=false` unless it is
  an intentional, documented configure-time dependency.

### G2. New-Project Golden Path

- `nandina new <path>` creates a project with a resolvable Nandina source dependency. Writing only
  `subproject('nandina')` without creating a wrap, submodule, or explicit local-source link is not
  sufficient.
- The source strategy is deterministic and testable without network access. Release projects use a
  pinned, hash-verified archive/wrap; Git and local-source options are explicit alternate providers.
- An end-to-end fixture executes `new -> meson setup -> meson compile` and verifies the generated
  resource package, application executable, and lock file.
- `nandina build` and `nandina run` use the same build directory and report actionable failures.
- A failed scaffold does not silently leave a directory that appears complete.

### G3. Resource And Media Path

- `resources.toml` remains the only human-maintained resource inventory.
- `meson compile` scans, validates, locks, and packages resources deterministically.
- `NanApplication` resolves the build-tree package and release executable-relative package.
- `widget::Image` can consume a packaged `ResourceKey` or resource URI without requiring an
  application to copy the image beside the executable.
- The Settings Gallery sample visibly exercises packaged PNG/JPEG resources through `res://` and
  bounded preview preprocessing.
- The render boundary accepts decoded resource bytes or a resource-backed texture input without
  exposing raylib types publicly.
- Page replacement does not force unchanged fonts or images to decode/upload again. Window-scoped,
  bounded residency caches reuse inactive resources and release them before the render device.
- Custom fonts can be registered from packaged resources; filesystem imports remain an explicit
  development/advanced path.

### G4. Basic Desktop Text Editing

- TextField preserves the existing grapheme-safe selection, caret, bidi movement, and composition
  model.
- Ctrl/Cmd-style select-all, copy, cut, paste, undo, and redo semantics are defined behind a
  platform-neutral clipboard/edit-command boundary.
- Read-only and disabled states cannot mutate text through shortcuts or semantics actions.
- Committed CJK input is manually verified on the supported Linux desktop session.
- Native pre-edit/candidate positioning is either implemented and tested or explicitly documented
  as a 1.x limitation after verifying that committed input remains usable.

### G5. Linux Platform Contract

- Executable discovery, resource roots, cache/user-data roots, DPI mapping, resize, and teardown are
  validated on the supported Linux environment.
- `ThemePreference::system` and `MotionPreference::system` either receive real platform updates or
  are documented/changed so they do not promise automatic OS observation.
- Settings is manually exercised at 1x and a non-1x framebuffer scale, in light and dark appearance,
  with keyboard-only navigation and CJK text.
- Known X11/Wayland differences are recorded in release notes.

### G6. Quality And Diagnostics

- The full Meson suite is green from a clean build.
- CI runs at least GCC and Clang, the external subproject fixture, resource workflow tests, the
  default/fallback dependency paths, and the optional physics configuration.
- ASan/UBSan runs cover the headless suite; any exclusions are recorded with reasons.
- `git diff --check` is clean and generated/build artifacts are absent from the source diff.
- Startup, resource, font, CLI, and project-configuration failures provide an actionable operation
  and path rather than a generic failure.

### G7. Release And Promotion Readiness

- Meson project version, CLI version, release notes, root license, and changelog agree.
- Public API and removed pre-1.0 interfaces receive one final audit.
- The exact experiment commit is tagged as an RC and recorded in the promotion manifest.
- The official repository migration passes the same clean build, full suite, external-consumer, and
  Settings manual acceptance gates.
- The final `v1.0.0` tag is created only in the official `NandinaUI` repository.

## 5. Ordered Closure Units

Execute the remaining work in dependency order:

1. **C0 — Contract and doc sync (complete)**: acceptance/promotion contracts are landed and stale
   capability/status claims are corrected; verified with a clean diff check and 42/42 tests.
2. **C1 — D3 scaffold closure (complete for experiment-local source mode)**: `new` links either the
   CLI's configured Nandina source or explicit `--nandina-source`, publishes from a sibling staging
   directory, and is covered by `new -> meson setup --wrap-mode=nodownload -> compile` including
   resources. A pinned official wrap/submodule remains a C6/C8 release-distribution task.
3. **C2 — D3 build/run/doctor (complete)**: project commands share build-directory metadata;
   `doctor` checks required tools, minimum versions/capabilities, and generated-project integrity.
4. **C2.1 — Independent CLI and SDK sources (complete)**: move the workflow tool to the sibling `NandinaCLI`
   repository; define layered software sources/mirrors, locked SDK resolution and verified cache;
   replace the default source symlink with a pinned archive wrap. The contract is
   `NANDINA_CLI_DISTRIBUTION.md`.
5. **C3 — Packaged image path (complete)**: ResourceManager/package bytes feed Image/texture
   loading through `res://`; the Settings logo is packaged by nanres. Verified by focused
   image/application-resource/settings-example tests and the 42/42 full suite.
6. **C4 — Desktop edit commands (complete)**: platform-neutral
   clipboard, cut/copy/paste, undo/redo, committed CJK tests, and read-only/disabled protections are
   automated. GNOME Wayland + fcitx5 committed Chinese input and Ctrl+A/Z/Y pass manually. The
   XWayland clipboard path bridges through `wl-clipboard`. The remaining C/X/V failure was traced
   to the embedded `EditableText` querying a tree it does not own; `TextField` now passes its scene
   clipboard explicitly. Hyprland end-to-end injection and owner copy/cut/paste acceptance pass.
   Candidate positioning remains a documented 1.x limitation.
7. **C5 — Linux platform truth (in progress)**: executable/resource paths, DPI,
   appearance/motion policy, and release limitations are tracked in `LINUX_PLATFORM.md`. C5.1 adds
   validated per-frame screen/framebuffer metrics and enables high DPI by default. C5.2 defines
   `system` as an atomically host-injected snapshot with light/full fallback and no automatic Linux
   observer promise. Settings 1x, non-1x, resize and teardown acceptance on the second device remains
   manual before this unit is complete.
8. **C5.3 — Window resource residency (in progress)**: keep Router page-instance semantics
   independent from render resources; add bounded LRU retention for font pipelines and shared RAII
   image textures, verify cross-page reuse, and preserve scene/cache/device teardown order. The
   contract is `RESOURCE_RESIDENCY.md`.
9. **C6 — D4 quality/distribution**: CI matrix, sanitizer lane, archive/recursive/offline source
   builds, SDK artifact publishing, release metadata, and install-distribution verification.
10. **C7 — Release candidate**: freeze, run every automated/manual gate, and prepare the promotion
   manifest.
11. **C8 — Official promotion**: execute `1.0_PROMOTION_PLAN.md`, validate in `NandinaUI`, and tag
   the official 1.0 release.

Do not insert new widgets, media systems, backends, or examples into C0-C8 unless they directly
close an acceptance gate.

## 6. Per-Unit Verification

Every code-bearing closure unit runs:

```sh
meson compile -C buildDir
meson test -C buildDir --print-errorlogs
meson compile -C buildDir nandina_settings_example
git diff --check
```

Resource/media units additionally run the resource and image-focused tests. Input/platform units
add the closest focused tests plus a written manual verification record. Distribution units must
create their consumer tree in a temporary directory and may not depend on an undeclared source-tree
path.

## 7. Release Decision

The 1.0 release is ready only when G1-G7 are all satisfied or an exception is explicitly recorded
in this document with owner, rationale, user-visible limitation, and target follow-up version.
Passing the existing unit suite alone is necessary but not sufficient.
